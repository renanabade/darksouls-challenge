# data/ds1 — Dark Souls: Remastered data set

Generated by the data pipeline (a separate repository: extraction from the game files, world graph, verification,
export and the phase A tests); do not edit by hand. This file is the contract between that pipeline and the product.

Game: DARK SOULS: REMASTERED, Steam build 10943698. Data version in `meta.json`. All files are UTF-8 JSON with sorted
keys; the export is deterministic (same inputs, same bytes). IDs are slugs of the English names and are stable across
exports as long as the names do not change.

## Conventions

- **Region ids** (`regions.json`) are the nodes of the progression graph. Every other file points to regions by id.
- **Requirement expressions** (`entrances.json` `requires`): `true`, `false`, `{"has": "<item or event>"}`,
  `{"region": "<region id>"}`, `{"all": [expr, ...]}`, `{"any": [expr, ...]}`. `has` names an item from
  `locations.json` (`item`), or a starting gift (only ever inside an `any`, as an alternative).
  Boss deaths and other milestones are items named like `"Taurus Demon Defeated"`.
- **Glitches** are not in the graph (`meta.glitches: false`).
- **Found** (`locations.found`): a pickup from a corpse or chest placed in the map, matched to the game's treasures by
  item lot, not by DSAP category. Excluded: the Firelink rescue chest, unused treasures, and treasures shown only when
  someone dies (`treasures.deathDrop`: a drop is not a found item). Every location has the field.
- **Names** come from the game's text where DSAP differs (boss "Four Kings").
- **Unverified** facts stay in the pipeline's notes; this data set contains only what passed the verification flow
  or is explicitly flagged (fields named `...Assumed`, `note`, `why`).

## Files

| File | Content |
| --- | --- |
| `meta.json` | Game, build, `dataVersion`, `start` region, `goal` item, DSAP logic options used, sources and licenses |
| `areas.json` | The game's 30 place names: `id`, `name`, `placeNameId` (PlaceNames text id), `dlc`, `regions` |
| `regions.json` | `id`, `name`, `area` (null only for `virtual` shop-logic nodes), `mandatory` (on every path to the goal) |
| `entrances.json` | Directed edges `from` → `to` with `requires`; `walkBack`: false when the way back on foot is known not to exist (one-way drop, scripted ride); true is the default and an assumption for plain walking edges; `origin`: DSAP, override (hand correction with `note`), way back |
| `locations.json` | Every item source DSAP lists (corpses, chests, drops, event rewards, shops), plus sources it lacks (category `NPC_GIFT`: Laurentius' Pyromancy Flame, from his talk script): `region`, `name`, `item`, `count`, `category`, `mandatory`, `found`, `kind` (`weapon`, `armor`, `ring`, `spell`, `good`, or `other` for graph events and renamed items; from the game's name tables), `unavailable` (bonfires only, optional: windows in which the bonfire is out or missing, each with `from` and `until` requirement expressions, `until` null when it never comes back or its return is not modeled, and `why`) |
| `treasures.json` | Game treasures only (corpse or chest): `region`, `map`, `lots` (lot chain heads), `container`, `hidden`, `eventControlled`, `rescue` (Firelink rescue chest for missed items), `perClass` (Asylum class kit), `deathDrop` (shown only when someone dies), `items` |
| `bonfires.json` | `name`, `region`, `flag` (lit), `entityId`. Warping needs the Lordvessel and sitting at a bonfire |
| `bosses.json` | `id`, `name`, `flag` (defeated), `region`, `mandatoryByGraph`, `earliestSphere`, `parts` (per body part: `hp`, `resist`, `immune` status list, `noDamage` damage types, `defense` per element (`phys`, `magic`, `fire`, `thunder`; NpcParam `def_*`, flat, 9999 = no damage; since 0.6.0), NpcParam `flags`), `requires` (hard requirements with evidence) |
| `milestones.json` | Progression flags (bosses, bells, Lordvessel, Lord Souls, Kiln): `id`, `name`, `flag`, `kind`, `region`, `earliestSphere`, `requires` (what reaching it means on the graph, as a requirement expression; boss milestones name the boss's death item) |
| `merchants.json` | `id`, `name`, `regions` (graph regions holding their shop locations; a virtual region is shared by every merchant who sells there), ShopLineupParam `rows` range, `stock` (`kind`, `id`, `name`, `price`, `quantity` (-1 = unlimited)), `variants` (talk script, row range, flag conditions that select it), `exclusive` (optional: stock groups of which a playthrough gets only one option, each with the `flag` and `when` that pick it) |
| `weapons.json` | Every named weapon row: `family`, `infusion`, `category`, `melee`, `req` (str/dex/int/fth), `baseDamage`, `scaling`, `casts`, `hands`, `dmgType`, `weight` |
| `spells.json` | Every named spell (Magic param): `id`, `name`, `item` (the name in `locations.json`, `Sorcery: Soul Arrow`), `school` (sorcery, miracle, pyromancy), `req` (int/fth), `slots` (attunement slots), `uses`, `damage` per element (from the attack of the spell's bullet and the bullets it spawns on hit; 0 for spells that deal none) |
| `armor.json` | Every named armor piece: `slot`, `weight`, `poise`, `defense`, `resist` |
| `classes.json` | Starting classes (level, stats, cell kit and full kit) and starting gifts |
| `traps.json` | Places with no walking exit: `exits` (`means`: jump, warp, darksign, homeward-bone, serpent, key, death; with `requires`), `notWorking` |
| `scripted-deaths.json` | Deaths caused by scripts; `countsAsDeath` false only for unavoidable, mandatory deaths (Seath's capture) |
| `mandatory.json` | Items and regions on every path to the goal, by removal analysis on this graph (after the overrides, with no starting item) |
| `overrides.json` | Not generated: the corrections the export applies on top of the DSAP graph (below) |

## Overrides

`overrides.json` is the one file here written by hand. It is versioned with the product so every correction to the
DSAP graph is reviewed in the open, and the export applies it, in order, every time it runs:

```json
{ "overrides": [
  { "id": "E9", "file": "entrances", "match": { "from": "<region id>", "to": "<region id>" },
    "op": "condition", "value": { "has": "<item>" }, "source": "m10_00_00_00 Event_11000532" }
] }
```

- `file` is a list file of this data set (`entrances`, `locations`, `merchants`, `bonfires`, ...); `match` picks
  exactly one record by the fields it lists (ids as exported).
- `op`: `add` appends `value` (nothing may match it yet: its `match` when given, else all of `value`); `remove` drops the record; `replace` sets the fields in
  `value`; `condition` adds `value` to the record's requirement (`field`, default `requires`) with an `all`.
- `source` cites the game: an event, flag, talk script, map or param row, or an in-game test. Never a private path.
- The export stops when a `match` finds no record or more than one, so a renamed region breaks the export instead of
  dropping the fix. The product tests (`packages/core/test/overrides.test.ts`) check that every override is applied
  to the exported files and cites the game.

## Known limits

- `mandatoryByGraph` for bosses depends on boss gates in the graph; the Bell Gargoyles and the Centipede Demon gates
  are encoded by overrides, but other fogs that only open on a boss's death may not be. Do not use it for the
  "bypassable boss" orders yet. It holds for a run with no starting item: the core computes which bosses a run needs
  from its class and gift (the Master Key makes the Taurus Demon optional).
- Walking edges are assumed two-way unless the pipeline lists them as one-way (`walkBack: false`).
- The Gravelord coffin (Catacombs ↔ covenant room by Nito) is not in the graph, and covenant rewards (e.g. Gravelord
  Sword) are not locations yet.
- Tail-cut weapons (e.g. Drake Sword) are not locations; weapons are exported at +0 only (no reinforcement levels).
- The two-hand Strength rule and the attunement slot table are not in the game params (the table is in the executable,
  whose code is protected); the core takes them from cross-checked sources (planning docs, docs/04).
- Spell damage is the base attack only: no status (poison, toxic) and no scaling with the catalyst.
